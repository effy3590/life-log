# Life Log｜生活记录与复盘

把吃饭、睡觉、运动和精力随手告诉 AI，让它整理记录、接受更正、定期复盘。无需手环，不绑定模型，不需要另外申请 API key。

这个仓库分享的是一套记录方法和本地台账工具。你可以从“今天吃了什么”开始，不必先把生活的所有数据收集齐。

**[下载技能安装包](https://github.com/effy3590/life-log/raw/refs/heads/main/life-log-v0.1.0.zip) · [查看技能指令](SKILL.md) · [复制提示词版](PROMPT.md)**

## 它能做什么

| 你说 | 它做 |
|---|---|
| “今天早餐吃了一个鸡蛋、一小碗粥。” | 按日期整理记录，简短确认，保存后回读 |
| “更正一下，粥剩了一半。” | 替换原条目的当前版本，保留更正，不重复累计 |
| “今天结束。” | 汇总已有记录，说明缺什么，不把漏记当成没吃 |
| “帮我做本周复盘。” | 看记录覆盖、可比变化、本人感受、未知项和一个容易做的下一步 |
| “我要换一个 AI，生成交接档案。” | 整理目标、近期情况、重要更正和原始台账位置，方便你主动带过去 |

照片、语音、手环导出都是可选输入，能否读取取决于使用的 Agent。没有这些能力就用文字记录。

把下面这段发给 Codex：

```text
请用 skill-installer 安装 https://github.com/effy3590/life-log 。
技能在仓库根目录，path 为 .，安装名称为 life-log。
安装后检查 SKILL.md 和相关文件是否齐全。
```

安装完成后，新发一轮消息：

```text
用 life-log 帮我开始记录生活。我最关心白天的精神状态，不想每天截图。
先告诉我数据会存在哪里，然后我们从今天开始。
```

通常下一轮就可使用；若技能仍未出现，再重启 Codex。安装器会处理当前环境中的目录，不需要你手动寻找。此仓库只含一个技能，位于根目录；不要遗漏 `path=.` 和名称。

## WorkBuddy：导入技能包

1. 点击本页上方“下载技能安装包”，保存 `life-log-v0.1.0.zip`。
2. 打开 WorkBuddy 的 **专家·技能·连接器 → 技能 → 添加技能 → 上传技能**，选择这个 ZIP。
3. 在“已安装”确认技能已启用；进入新对话，发送上面的开始记录示例。

界面名称可能随版本变化。官方目前说明：对话安装针对技能市场里的技能，自建技能包通过上传导入。因此这里提供专用 ZIP，不承诺把任意 GitHub 链接发给 WorkBuddy 就能自动安装。[官方安装说明](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Skills-Market)

如果导入没有出现，先确认包内有 `life-log/SKILL.md`，再检查版本和导入错误。此项目没有提交 WorkBuddy 技能市场，不需要在市场搜索它。

## 其他 Agent / 普通聊天工具

- 支持 [Agent Skills](https://agentskills.io/specification) 的工具：将完整技能文件夹按该工具的官方说明导入，文件夹名使用 `life-log`。具体安装入口和脚本权限需自行核对。
- 只有聊天功能，或没有技能安装入口：打开 [PROMPT.md](PROMPT.md)，复制其中的提示词即可。不能读写文件时，AI 只能输出供你复制保存的台账。

这是一套可移植的技能文件，**不是所有 AI 工具通用的一键安装器**。

## 日常怎么用

开始时说明一个想观察的问题，以及你的记录习惯。之后随手说具体发生了什么，不需要每天交完整作业。

```text
今天午饭吃了一碗面，汤没喝完，下午精神一般。
昨天准备跑步，但最后没去，帮我记成未完成。
更正 4 月 12 日早餐，牛奶只喝了半盒，不是一整盒。
今天结束，看看还有什么信息不清楚。
复盘 4 月 6 日到 12 日，只按已有记录分析。
生成交接档案，把需要带走的台账也导出到我指定的文件夹。
```

示例全部虚构，不是作者的健康记录或效果证明。

## 数据存在哪里

由 Agent 告诉你实际位置。默认在你当前工作区创建独立的 `life-log-data`，不能放在技能安装目录里。档案、原始台账、复盘分开保存，更新或卸载技能不应影响这些文件。

有 Python 3.10+ 时，附带的 `ledger.py` 保存事件历史、校验格式、处理更正和导出，只有标准库依赖。没有 Python 或不能执行命令时，使用 Markdown 台账，AI 应说明当前模式和是否真的保存成功。脚本使用方式见 [LEDGER.md](LEDGER.md)。

这个 Skill 不自带云端服务器，不向开发者发送记录，不自动接入设备，也不后台监控。**文件保存在本地，不等于模型推理完全离线**：你使用的 Agent 仍可能把任务相关内容交给其模型服务。请按自己的需要选择提供哪些信息。

不要把生活档案提交到公开仓库，也不要在公开 Issue 中贴个人健康数据。换聊天或换工具时，需要主动提供最新交接和台账；不会自动同步。

## 这套方法的边界

它帮你把事情记清楚、回头看得明白。缺失不是零，计划不等于完成，睡眠设备读数是估算，两个变化同时出现不证明因果。它不提供疾病诊断、药物调整或健康结果保证。

## 开发与核验

```bash
python3 -m unittest -v test_ledger.py
```

测试使用临时目录和虚构数据，重点核对新增、更正、重试、损坏日志拒绝写入、导出和数据目录边界。行为检查还需验证 Agent 是否遵循指令；程序测试通过不代表所有模型的分析都准确。
